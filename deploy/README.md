# Deploy

Configures the OS/environment on the EC2 instance Terraform provisions (see
`../terraform/README.md`). Plain POSIX shell over SSH — no Ansible, no Python on the
target. Alpine's cloud AMIs (3.15+) ship without sudo/doas, so `../terraform/compute.tf`
sets **root's** SSH key directly via `user_data`; everything here connects as root.

`.env` (`HOST=`, `KEY=`) is generated by `terraform apply` — don't hand-edit it.

## Steps (run in this order by `deploy.sh`)

1. **00-common.sh** — base packages, timezone, app user/group, swapfile, sshd hardening.
2. **10-sysctl.sh** — C10K sysctl tuning for a high-concurrency epoll TCP/HTTP server.
3. **20-toolchain.sh** — `build-base`/`cmake`/`git` for on-box aarch64/musl compilation.
4. **30-logging.sh** — logrotate + dcron, since the server writes its own log files.
5. **40-app-service.sh** — `/opt/temperingworks` layout + OpenRC service. Left enabled
   but stopped until a real binary exists.

`optional/privileged-port.sh` is opt-in (not run by `deploy.sh`) — run it manually once
ready to move off port 8080 onto the standard port 80 via `cap_net_bind_service`.

## One-time sshd_config.orig capture

Before running `deploy.sh` against a **fresh** instance for the first time, capture
Alpine's shipped default so it's kept as reference material next to `files/sshd_config`:

```
ssh -i ~/.ssh/mykeypair20260813.pem root@<ip> cat /etc/ssh/sshd_config > files/sshd_config.orig
```

Commit the resulting file in place of the placeholder, then run `deploy.sh`.

## Run

```
./deploy.sh                # picks up HOST/KEY from .env after `terraform apply`
./deploy-app.sh <binary> <frontend-dist-dir>   # once a real build exists
```
