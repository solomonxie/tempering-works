# Deploy

Configures the OS/environment on the EC2 instance Terraform provisions (see
`../terraform/README.md`). Plain POSIX shell over SSH — no Ansible, no Python on the
target. Alpine's cloud AMIs (3.15+) ship without sudo/doas, so `../terraform/compute.tf`
sets **root's** SSH key directly via `user_data`; both scripts here connect as root.

`.env` (`HOST=`, `KEY=`) is generated by `terraform apply` — don't hand-edit it.

## deploy.sh

One pass, run once per fresh instance: base packages, sshd hardening, C10K sysctl
tuning, C++ toolchain, log rotation, and the app's OpenRC service (`/opt/temperingworks`,
enabled but left stopped until a binary exists). Pipes its whole body straight into
`ssh root@host 'sh -s'` — no files to push first.

```
./deploy.sh                # picks up HOST/KEY from .env after `terraform apply`
```

## deploy-app.sh

Run repeatedly, whenever there's a new build: rsyncs a binary + frontend `dist/` to the
server and (re)starts the service.

```
./deploy-app.sh <binary> <frontend-dist-dir>
```

## Moving to port 80

`deploy.sh` leaves the service on port 8080. To move to the standard HTTP port instead
of running as root, once a binary is deployed:

```
ssh -i <key> root@<ip> '
  apk add --no-cache libcap
  setcap cap_net_bind_service+ep /opt/temperingworks/bin/temperingworks-server
  sed -i "s/^APP_PORT=.*/APP_PORT=80/" /etc/conf.d/temperingworks-server
  rc-service temperingworks-server restart
'
```

Also open port 80 in `terraform/network.tf`'s security group (`app_http_port`) and re-apply.
